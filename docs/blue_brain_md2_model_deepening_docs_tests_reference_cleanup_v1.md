## 4) Diagnostics, contract, and consumer-read semantics

The following distinctions are the maintenance-facing contract and must not drift:

- model state is not contract state,
- model state is not region authority,
- diagnostic model output is not operational authority,
- `diagnostic-only` has no advisory support,
- `caveated advisory-only` is not strong operational support,
- `deferred`, `blocked`, and `insufficient` are no-support states,
- `non-canonical/internal-only` has no canonical Runtime, Selection, Reference, or Execution consumer read,
- canonical `Amygdala ↔ Thalamus` reads use the bounded advisory/diagnostic consumer-read class only.

The canonical support classes remain those exposed by `BlueBrainMd1FirstDeepeningContractSupportClass`; documentation must not reinterpret diagnostic or caveated model output as stronger authority than the code returns.

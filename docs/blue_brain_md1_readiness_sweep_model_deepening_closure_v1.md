## 3) Model-deepening line

Canonical first-deepening surfaces:

- Input: bounded Kuramoto-like input surface only; no raw action state, queues, memory-store internals, compute backends, policy authority, or safety state.
- State: relation-local `Amygdala ↔ Thalamus` state; not a contract state and not region authority.
- Output: classification-only advisory/caveated/deferred/blocked/insufficient/diagnostic/non-canonical states.
- Diagnostic/model: model diagnostics only; `diagnostic-only` has no advisory support.
- Contract: support class is separate from model and diagnostic class: advisory bounded support, caveated bounded support, deferred no support, blocked no support, insufficient no support, diagnostic-only no advisory support, or non-canonical no support.

Runtime, Selection, and Reference are bounded-informed through one consumer-read class: `consistent bounded advisory/diagnostic read` for the canonical first candidate and `no canonical consumer read` for non-canonical/internal-only or not-opened paths.

Explicitly not operative in MD1 Prompt 4:

- no second deepening candidate,
- no direct Action control,
- no direct Execution control,
- no Retry orchestration,
- no Planner/Agent logic,
- no Policy/Governance authority,
- no automatic Memory persistence,
- no Safety override,
- no Compute effect or Compute-Core expansion,
- no global Kuramoto platform,
- no global HH platform,
- no general model platform.

## 4) Model, diagnostics, and contract boundaries

The closure line pins these distinctions:

- model state is not contract state,
- diagnostic model output is not operative authority,
- `diagnostic-only` is not advisory support,
- `caveated advisory-only` is not strong support,
- `deferred`, `blocked`, and `insufficient` remain no-support states,
- `non-canonical/internal-only` is not consumable by Runtime, Selection, Reference, or Execution,
- abstract functional surfaces remain abstract,
- Kuramoto-like means bounded coupling/synchrony/gating/timing only,
- HH-like candidates remain simulation-only/diagnostic-only or later-selective; none is productive in MD1 Prompt 4.

## 5) BlueBrain cross-line compatibility

MD1 Prompt 4 preserves the existing lines:

- BB10/BB12 bounded dynamics remains advisory-only and guard-bound.
- BB16 dynamics ↔ execution feedback remains bounded and cannot trigger execution or retry.
- BB17 context/memory/reference hardening remains intact; MD1 does not persist memory.
- BB19 runtime/selection contract line remains intact; MD1 only informs through bounded reads.
- BB21 execution/reference interaction remains intact; execution references remain references, not action authority.
- IR1 remains the leading inter-region architecture; MD1 does not rewrite it into a model architecture.
- Internal-only/non-canonical paths remain non-operational.

## 6) Compute-core closure

MD1 does not reopen compute. The compute line remains:

- final Compute line,
- outward-facing contracts only,
- maintenance-only Core,
- no new backend, no new invocation semantics, no new compute authority from model-deepening outputs.

## 7) Next direction decision

Decision: prioritize **Maintenance of the existing first model deepening**, not a second deepening candidate.

Technical reason:

1. The first deepening is now stable enough to name and consume diagnostically/advisory, but it is still valuable to keep surface/contract/diagnostic distinctions visible under future Runtime/Selection/Reference changes.
2. `Amygdala ↔ Basal Ganglia` remains the only plausible second bounded relation candidate, but opening it now would increase action-gating ambiguity and risk blurring selection mediation with action control.
3. HH-heavier paths remain too expensive and too easy to misread as productive model authority; they should wait for a separate rescope with simulation-only/diagnostic-only guard proof.
4. Broader model work has lower leverage than maintaining the first deepening's guards, docs, and targeted checks.

Therefore `BLUE_BRAIN_MD1_NEXT_MODEL_DEEPENING_DIRECTION` is `MaintainFirstDeepeningBeforeSecondCandidate`.
